# M1: Data you can trust

Status: built on branch `claude/jeron-m1-data-k9pxtj` (stacked on M0), awaiting review.

## Goal (spec section 11)
Bhavcopy history (≥ 8 years), corporate-action adjustment, a second-source
cross-check, a daily data-quality report and a spot-check page.
*Accept:* 20 stock-dates spot-checked against the broker's chart match.

## Data sources
| What | Source | Notes |
|---|---|---|
| Daily prices (source of truth) | NSE bhavcopy from `nsearchives.nseindia.com` | Legacy `cmDDMONYYYYbhav.csv` until 2024-07-05, UDiFF `BhavCopy_NSE_CM_...` from 2024-07-08. Series EQ, BE, BZ. Raw, unadjusted. |
| Corporate actions | NSE "PR" bundle (`PRddmmyy.zip`), file `bc<date>.csv` | NSE's own list of ex-dates and purposes ("BONUS 1:1", "FV SPLT FRM RS 5 TO RE 1", "INTDIV - RS 21 PER SH"). Collected daily. |
| Second source | Yahoo Finance chart API (`SYMBOL.NS`) | Prices are split-adjusted by Yahoo; we undo that with Yahoo's own split events, then compare raw closes. Also gives split and dividend events. |

Why not the bhavcopy's previous-close column for corporate actions: NSE does not adjust
it on ex-dates (RELIANCE on 2024-10-28 shows 2,655.70, the pre-bonus close), so the
exchange's corporate-action file is needed. See decision 0003.

## What was built
- `app/data/http.py`: polite downloader (1 request/second, retries NSE's temporary
  403 "Access Denied" and Yahoo's 429; 404 = not published).
- `app/data/nse.py`: URLs, both bhavcopy formats, corporate-action purpose parser, an
  on-disk cache of raw files (`JERON_DATA_DIR`).
- `app/data/yahoo.py`: second source, un-adjusted to raw prices.
- `app/data/adjust.py`: splits and bonuses adjust earlier prices by an exact factor;
  dividends only on request (total-return view); rights issues and demergers are
  logged but not applied. Duplicate listings with a revised ex-date are resolved by
  which date the price actually gapped.
- `app/data/crosscheck.py`: close-by-close comparison (flag > 0.5%) and split/bonus
  agreement between sources.
- `app/data/quality.py`: the daily report (below).
- `app/data/pipeline.py` + `app/cli.py`: `backfill`, `crosscheck`, `quality`, `daily`,
  `holidays` commands. Every job is resumable.
- API: `/data/status`, `/data/quality`, `/data/quality/{date}`, `/data/symbols`,
  `/data/spot-check`, `/data/spot-check/sample`.
- Web: `/data` (status, scan allowed or not, daily reports), `/data/quality/{date}`,
  `/spot-check` (raw vs adjusted vs Yahoo, EMA 20/50/200, RSI 14, ATR 14, the
  adjustment log, and "give me 20 stock-dates to check").

## Schema changes (migration `7b1f2c9d4e10`)
- `instruments` unique on (exchange, symbol); `series` is the latest series, and each
  bar records its own series, so a stock moving EQ → BE keeps one history.
- `daily_bars.series`.
- `corporate_actions`: unique per (instrument, source, ex-date, type, text) so daily
  re-listings don't duplicate; `created_at`.
- `source_files`: per source and day, whether the file was downloaded, not published
  (holiday) or failed, with its SHA-256 and row count.
- `data_quality_reports`: one per trading day.

## Quality checks (per trading day)
| Check | FAIL when | WARN when |
|---|---|---|
| trading_day | calendar trading day with no bhavcopy, or download failed | NSE traded on a calendar holiday |
| row_count | fewer than 80% of the previous day's stocks | |
| invalid_rows | | rows with impossible prices (not stored) |
| zero_volume | | any stock with zero volume |
| big_moves | | close moved > 20% with no split/bonus, or on an unadjusted rights issue/scheme |
| stale_prices | | same close five sessions running |
| cross_check | > 5% of checked closes differ by > 0.5% | any close differs; not run; second source missing > 20% |
| corporate_actions | | a split/bonus one source has and the other doesn't |

`/data/status` returns `scan_allowed: false` when the latest report FAILs; M2's scan
must check it.

## Known gaps
- Rights issues, demergers and schemes are not price-adjusted (the files lack the
  issue price or demerged value). They are flagged when they move the price > 20%.
- Symbol changes (e.g. a renamed company) start a new history; linking by ISIN is
  M2 work alongside the universe.
- Index membership history (Nifty 500) is not loaded yet; M2 needs it for the universe.
- NSE's bot filter blocks bursts; a full backfill takes about 1.5 hours at one
  request per second and can simply be re-run if interrupted.
