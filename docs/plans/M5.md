# M5: Web app and Telegram alerts

Status: in progress (branch `claude/jeron-m4-6px1i8`).

## Goal (spec section 11)
Dashboard, stock page, journal basics.
*Accept:* scan -> signal -> Telegram alert -> journal works end to end.

## Starting point
No strategy passes section 6 yet (M3 report; PR #8 confirmed the numbers), so every
signal today is **research only**. Ground rule: no signal without a backtested strategy
behind it, so research-only signals are never sent as trade alerts. They do appear in
the daily summary under their own heading ("research only, not trades"), so the whole
chain is visible every day. A setting can turn on per-signal alerts for them, clearly
marked, for testing.

## Scope
1. **Alerts** (`app/alerts/`).
   - Telegram Bot API (`sendMessage`, plain HTTPS, no extra library). Email (SMTP) is
     the backup: used when Telegram is not set up or a send fails, if SMTP is set.
   - One message per new signal of a live-eligible strategy: ticker, setup, entry zone
     and validity, stop, T1/T2, shares and rupees at risk, reward:risk, conviction, the
     reasons, event risk, the strategy's backtest numbers, and a link to its journal
     entry.
   - One daily summary after each `daily` run: data quality, scan result, regime, new
     signals (live and research only), each paper account's equity, open positions and
     heat, and journal positions still open.
   - Every alert is stored once (`alerts` table, unique per channel and key), so a
     re-run never sends twice; failures are stored and retried on the next run.
   - `python -m app.cli alerts [--date D]` sends what is due; `daily` runs it at the end.
     `python -m app.cli telegram --setup` finds the chat id after you message the bot;
     `--test` sends a test message.
   - Settings: `JERON_TELEGRAM_BOT_TOKEN`, `JERON_TELEGRAM_CHAT_ID`,
     `JERON_ALERT_RESEARCH_SIGNALS` (default off), `JERON_SMTP_*`, `JERON_ALERT_EMAIL_TO`,
     `JERON_WEB_URL` (for links). Secrets only in `.env`.
2. **Journal basics** (spec section 8, first part).
   - Every signal is auto-logged as *pending*. I mark it taken, skipped or modified,
     with a reason, and enter fills (buy/sell, date, shares, price, charges). Manual
     trades without a signal are allowed.
   - Derived per entry: shares held, average entry, realised and open P&L, R multiple
     (against the signal's stop, or a stop I enter), and status (open/closed).
   - Per strategy: signals, taken, skipped, closed trades, win rate, average R,
     expectancy, "followed the plan" vs "deviated". Tradebook import and the weekly
     summary are M7.
3. **Web app.**
   - Dashboard (home): regime banner, data-quality status of the newest day, today's
     signals (live first; research only labelled), open positions (journal and paper)
     with R so far, each paper account's heat, and pending journal decisions.
   - Stock page `/stocks/[symbol]`: candlestick chart of split/bonus-adjusted prices
     (TradingView Lightweight Charts) with entry zone, stop and targets of the latest
     signal drawn on it, the technical score history, the signals for the stock, the
     strategy that fired with a link to its backtest report card, and journal entries.
     Fundamentals, news and results dates are M6.
   - Journal page: pending signals, open and closed entries, per-strategy stats, and a
     form per entry (decision, fills, notes). Forms post through Next.js server actions,
     so the browser never calls the API directly.
   - Installable PWA: web manifest and icons.
4. **API.** `/dashboard`, `/stocks/{symbol}` (bars, score history, signals),
   `/journal`, `/journal/{id}`, `PUT /journal/signal/{signal_id}`, `POST /journal`,
   `POST /journal/{id}/fills`, `DELETE /journal/fills/{id}`, `/alerts`.

## Schema changes
`alerts`, `journal_entries`, `journal_fills` (one migration).

## Spec readings (please confirm)
- Research-only signals are not alerted one by one (setting to turn on), only listed in
  the daily summary.
- Single-user login (password + TOTP) waits for the move to a cloud VM or the broker
  token (M7), since Jeron runs on your laptop for now. Until then, don't expose port
  3000 or 8000 beyond your machine.
- Telegram buttons ("taken"/"skipped" in the chat) need a running bot listener; for now
  each alert links to the journal page instead.

## Tests
- Alert formatting (signal message, daily summary, research-only section, Telegram's
  4,096-character limit split), Telegram and SMTP senders against fakes, fallback to
  email, idempotency and retry.
- Journal maths: average entry, partial exits, realised/open P&L, R multiple, stats.
- On Postgres: scan -> paper signal -> alert stored and sent (fake Telegram) -> journal
  entry marked taken with fills -> stats, for a live-eligible strategy; research-only
  signals appear only in the summary; API endpoints.
- Web: lint, typecheck, build.

## Acceptance checks
- `uv run pytest -q` covers the end-to-end chain above.
- On real data: `daily` sends the summary; a test message reaches Telegram once you add
  the bot token.
